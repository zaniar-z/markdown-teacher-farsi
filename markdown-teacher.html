از مبتدی تا حرفه‌ای — ساختاری هوشمند برای یادگیری عمیق

مقدمه و فلسفه

Markdown یک زبان نشانه‌گذاری سبک (lightweight markup language) است که با هدف خواناییِ متنِ ساده طراحی شده. ایدهٔ اصلی: متن باید حتی در حالت خام هم قابل خواندن باشد.

چرا Markdown؟

  • سادگی: بدون تگ‌های پیچیده HTML
  • قابل انتقال: فایل‌های .md در همه جا باز می‌شوند
  • کنترل نسخه: diff خوانا در Git
  • استفاده گسترده: GitHub، GitLab، Notion، Obsidian، Discord، Reddit، Stack Overflow،...

سطوح سربرگ (Heading Levels)

شش سطح از h1 تا h6 با نماد #:

# سطح 1 - عنوان اصلی سند
## سطح 2 - فصل
### سطح 3 - بخش
#### سطح 4 - زیربخش
##### سطح 5 - جزئیات
###### سطح 6 - ریزجزئیات

قوانین مهم

  • فاصله بعد از # الزامی است (#Title غلط، # Title درست)
  • فقط یک h1 در هر سند (بهترین تمرین SEO و دسترس‌پذیری)
  • پریدن از سطح ممنوع است (از h2 به h4 نروید)

کاراکترهای خاص (Escaping)

برای نمایش خودِ کاراکترهای نشانه‌گذاری (به‌جای اعمال شدن‌شان)، قبلشان یک \ بگذار:

  • \*متن\* → نمایش می‌ده *متن* (نه متنِ کج)
  • \# → به‌جای سربرگ، خودِ #
  • \\ → یک بک‌اسلش
\*این پراکنده نیست\*
\# این سربرگ نیست
\\ بک‌اسلش نوشتن

لیست‌ها: مرتب، نامرتب، و تو در تو

لیست نامرتب (Unordered)

استفاده از -، *، یا + (ترجیح: - برای ثبات):

- مورد اول
- مورد دوم
  - زیرمورد (تورفتگی 2 فاصله)
    - زیرِ زیرمورد (تورفتگی 4 فاصله)
- مورد سوم

لیست مرتب (Ordered)

شماره‌گذاری خودکار؛ عدد اول مهم است، بقیه نادیده گرفته می‌شوند:

1. قدم اول
1. قدم دوم (رندر می‌شود 2.)
1. قدم سوم
   1. زیرقدم
   1. زیرقدم دیگر

لیست وظایف (Task Lists) — GFM

- [x] انجام شده
- [ ] در انتظار
- [ ] ~در حال انجام~ (ترکیب با strikethrough)

markdownlint — قوانین مهم

markdownlint قوانین را کد به کد (مثل MD013) شماره‌گذاری کرده؛ با آنها «چه چیزی اشتباه است و چرا» را می‌فهمی:

  • MD013 — طول خط: هر خط بیشتر از ۸۰ نویسه اخطار می‌گیرد. برای فارسی عملاً غیرفعالش کنید (خطوط فارسی بلند می‌شوند).
  • MD024 — سربرگ تکراری: دو ## با عنوان یکسان در یک سند، ممنوع (گیج‌کننده است).
  • MD033 — HTML خام: هشدار درباره تگ‌های HTML در متن؛ خاموشش کنید اگر عمداً HTML می‌نویسید.
  • MD041 — اولین سربرگ h1: سند باید با # شروع شود، نه مستقیم ##.

معرفی Obsidian

Obsidian یک برنامهٔ دسکتاپ (ویندوز، مک، لینوکس) برای مدیریت دانش شخصی (PKM) است که یادداشت‌ها را به‌صورت فایل‌های Markdown ساده روی سیستم خودت ذخیره می‌کند؛ یعنی هیچ سرور ابری واسطی در کار نیست و فایل‌ها همیشه در اختیار خودت هستند.

مفهوم Vault

هر پوشه‌ای که به Obsidian معرفی کنی یک Vault (خزانه) می‌شود؛ داخل آن هر فایل .md یک یادداشت است. چون همه‌چیز Markdown خام است، همان مهارتی که در بخش‌های قبل یاد گرفتی (سربرگ، لیست، کد، جدول) دقیقاً همین‌جا کاربرد دارد.

لینک دوطرفه (Wikilinks)

ویژگی اصلی Obsidian، لینک‌دهی بین یادداشت‌هاست:

این ایده به [[یادداشت دیگر]] مرتبط است.
تصویر: ![[diagram.png]]

وقتی یادداشت A به B لینک می‌شود، در B به‌صورت خودکار یک Backlink ثبت می‌شود و می‌توانی رابطهٔ بین ایده‌ها را در نمای Graph View به‌صورت شبکه‌ای از گره‌ها ببینی.

افزونه‌ها (Plugins)

  • Core plugins: امکانات رسمی داخل خود برنامه (Graph view، Daily notes، Templates، ...)
  • Community plugins: هزاران افزونهٔ متن‌باز از جامعهٔ کاربران، برای همه‌چیز از تقویم گرفته تا اتوماسیون

نصب و شروع کار (ویندوز)

مراحل نصب

  • از سایت رسمی obsidian.md نسخهٔ ویندوز را دانلود کن (رایگان برای استفادهٔ شخصی)
  • فایل نصبی را اجرا کن؛ نیازی به حساب کاربری اجباری نیست
  • در اولین اجرا یک Vault جدید بساز یا یک پوشهٔ موجود را به‌عنوان Vault باز کن

محیط کار

  • ستون وسط: ویرایشگر Markdown (حالت Live Preview یا Source)
  • سایدبار چپ/راست: درخت فایل‌ها، جست‌وجو، Graph view، Backlinks
  • Command Palette (Ctrl+P): دسترسی سریع به هر دستوری بدون ماوس
  • Quick switcher (Ctrl+O): پرش سریع بین یادداشت‌ها

سازمان‌دهی

می‌توانی از پوشه‌بندی سنتی استفاده کنی، یا فقط با لینک و تگ (#tag) ساختار بسازی — بسیاری از کاربران Obsidian ساختار درختی پوشه را کنار می‌گذارند و به شبکهٔ لینک‌ها تکیه می‌کنند.

اتصال Obsidian به ایجنت‌های هوش مصنوعی

چون Vault چیزی جز مجموعه‌ای از فایل‌های متنی روی دیسک نیست، وصل‌کردنش به ابزارهای هوش مصنوعی و ایجنت‌ها خیلی طبیعی است. چند مسیر رایج در جامعهٔ Obsidian:

۱. افزونهٔ Local REST API

این افزونهٔ محبوب یک سرور محلی روی سیستم خودت بالا می‌آورد که به یادداشت‌های Vault دسترسی HTTP می‌دهد (خواندن، نوشتن، جست‌وجو). ایجنت‌ها یا اسکریپت‌ها می‌توانند از طریق این API با یادداشت‌ها کار کنند، بدون این‌که فایل‌ها را مستقیماً دستکاری کنند.

۲. سرورهای MCP برای Obsidian

در جامعهٔ متن‌باز، چند پروژهٔ MCP server (پروتکل اتصال ایجنت به ابزار) برای Obsidian ساخته شده که روی همان افزونهٔ Local REST API یا مستقیماً روی فایل‌های Vault کار می‌کنند. با وصل‌کردن چنین سروری به یک ایجنت (مثلاً Claude)، ایجنت می‌تواند یادداشت‌ها را بخواند، جست‌وجو کند یا یادداشت جدید بسازد.

۳. افزونه‌های هوش مصنوعی داخل خود Obsidian

افزونه‌هایی مثل ابزارهای جست‌وجوی معنایی (embedding-based search) یا دستیارهای نوشتاری، مستقیم داخل Obsidian نصب می‌شوند و به Vault به‌عنوان یک پایگاه دانش برای پاسخ‌گویی و تولید محتوا نگاه می‌کنند.

نکات امنیتی

  • پورت سرور محلی را هرگز مستقیماً روی اینترنت باز نکن؛ فقط برای دسترسی محلی (localhost) استفاده‌اش کن
  • کلید API را مثل رمز عبور نگه‌دار و در فایل‌های عمومی/گیت‌هاب قرار نده
  • قبل از دادن دسترسی نوشتن به یک ایجنت، از Vault یک نسخهٔ پشتیبان (یا Git) داشته باش
